## Architecture choices

- **Why a file, not `config.json` or UserDefaults:** `config.json` is hand-edited, saved with a debounce, and moved aside if it's invalid. That would quietly reset the note and reauthorize the key. UserDefaults can't report write failures. A second keychain item would share the keychain's failure. The file write is atomic and reports errors, and it lives under the composition's configuration directory, so it is isolated with test configs. The note is scoped by the keychain service name.
- **Why no automatic delete at launch:** if a save succeeded but clearing the note failed, deleting at launch would destroy a validated key. Not using the key is the safe default; the user can remove it again or re-save.
- Key state moved from a single `keyChanges` counter to an operation queue with outcomes applied in order. `UnnotedKeyChange` (`.removal` / `.save`) and `canUseKey` are new observable/API surface.

## Real uncertainties and limits

- **Storage-failure limits (exact):** (1) If the keychain delete fails **and** writing the note fails, the key is unused now, but after a restart it would be read and used again. Settings says this (`unnotedKeyChange == .removal`). (2) If a save succeeds but clearing an earlier note fails, the new key is used now, but after a restart it's treated as removed until it's saved again. Settings says this, and after the restart the generic "A removed key is still in your keychain" text describes the new key. (3) If someone deletes the note file by hand, the removal is forgotten. (4) A note left behind after a successful delete (clear failed) only means a key field is shown, and the next save clears it.
- Compile risks: `withTaskCancellationHandler` around `operation.value`; `@MainActor` closure captured into the queued `Task`; `nonisolated final class LoopbackRedirects: NSObject, URLSessionTaskDelegate` with the async redirect method (if the SDK's `URLSessionTaskDelegate` isn't `Sendable`, passing it to the `@concurrent` `HTTP.send` may need adjusting); `nonisolated static var defaultFileURL`; `OSAllocatedUnfairLock` in the memory record; switch expressions in `ServiceDemand.limited`.
- Test expectations for Sol: `OpenRouterKeyStore(read:save:delete:)` still compiles, and its removal record is in-memory per instance. Restart tests should pass one shared `OpenRouterKeyRemovalRecord` to both service instances. The existing test "raw page offsets advance…" calls `loadMoreKeys()` 19 times in a row. Since pass3's 15 s gap (still present, now measured from dispatch), that can only pass if `eventually` waits that long. This is a test/contract conflict for Sol to resolve, not a change I made.
- The builder now starts only its own widget's services. A builder preview that relied on unrelated services would lose data; I found none (Railway, Codex sessions and Models only need their own).
- Not addressed, out of scope: `DesktopPictures` reads the wallpaper store at launch whatever the composition. `make dev`'s `pkill` behaviour is unchanged.
