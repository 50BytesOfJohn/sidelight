## Details lifecycle and state decisions

Use a small explicit state model, not independent visibility booleans: globally shown/hidden, plus optional session `{originDisplayID, consumer/widgetID, initial selection, catalogue state, generation}`. **Assumption:** one details session app-wide initially. A request from another display atomically returns the old display to main and replaces main on the new display. Same-session open focuses existing details; changing consumer replaces content without an unnecessary geometry round trip.

- Open from actual rendered display context, not mouse location or guessed primary display. Manager/build previews must not replace a real panel; disable the details affordance there or present an ordinary preview inside the manager.
- Publish effective occupied regions once, main→details on origin; other displays retain main strips. Main hides without invoking its ordinary hide restoration. Details is full visible-height, clamped to originating display; width stays 360 unless screen physically cannot accommodate it.
- Generic chrome owns title/close/accessibility, Escape and focus; content owns search/filter/sort/expanded rows. Start with a key-capable nonactivating `NSPanel`, `hidesOnDeactivate = false`, compatible main-panel Spaces behavior. Explicitly focus search on open; handle standard editing key equivalents. No activation-policy change merely for browsing. Nonactivating editing is **unverified**; Sol validates before selecting a justified activating fallback.
- Close atomically changes details→current main strip, restores eligible windows, destroys hosted content and clears search/transient catalogue state. Initial filter/sort come from clicked block; details changes never write widget config. Attempt to return focus only to a still-valid prior window, without stealing focus after the user selected another app.
- Toggle hide releases effective reservations in ONE transition to empty, applies conditional restoration, retains session/query/scroll but stops details demand. Toggle show transitions empty→effective details/main strips and takes new frame baselines; details reappears without resurrecting stale restoration records. Close shortcut while hidden discards session without showing panels; no-op if absent.
- Origin widget removal/hidden placement, disabled origin panel or disconnect closes session. Geometry/orientation changes while open recompute main/details in one transition; reset affected baselines conservatively, never restore coordinates from disconnected displays. Other displays continue normally. Do not auto-close on Space switch; never mutate windows on an inactive Space.
- Hidden underlying widgets get an assumed **5-second demand grace** via DelayedTask, then pause; they stop rendering/ticking immediately. Existing sleep/lock unseen grace remains 60 seconds. Details holds only catalogue demand, never all widgets. If another panel or manager still needs a resource, retain it. Global shortcut hide stops demand immediately.

## Reservation and restoration algorithm

Atomic means one logical old→new transition with no intermediate empty reservation, not an OS guarantee of simultaneous AX operations. AX can visibly perform position/size writes separately.

1. Put the transition ledger in the existing avoider/shared coordinator. Snapshot old/new regions, display geometry, eligibility and current frames before writes. Reentrancy/generation guards and suppression/coalescing of self-generated AX notifications prevent a second avoidance sweep. Defer while the mouse is dragging; superseded transitions use latest geometry. Logical occupancy is independent of fade alpha. No animation-completion callback may resurrect an old region.
2. Only trusted, avoidance-enabled, regular standard, non-minimized/non-fullscreen windows on originating display and active Space participate. Own windows are excluded. Public visible-window evidence may be correlated with AX windows; ambiguous membership must skip mutation, not guess by title alone. Do not introduce private Space APIs or request Screen Recording permission. Coordinate calculations use existing primary-screen-height conversion, including negative display origins.
3. Identity: retain AX element equality (`CFEqual`) + PID and process launch identity for the live ledger, scoped to display/transition. Never title as identity; never persisted IDs. Invalidate on process termination/window disappearance/display removal. If identity or current-Space membership cannot be established, skip restoration.
4. Record both **original frame** and **actual app-accepted frame after Sidelight writes**, with transition generation. Preserve earliest baseline during self-generated avoidance; accepted frame may differ from request. A failed/refused write must not create a fictitious successful adjustment. Keep separate baseline layers for main show/hide versus details takeover: closing details targets frame before details, hiding all targets before main reservation. These must compose in the same owner, not competing controllers.
5. Side→same-side details: apply existing shift/clip policy only to newly encroached space; windows already clear do not move. For a window touching old boundary, target new boundary with the same spacing convention, preserving far edge for clip or size for shift. If main is wider than details, do not blanket-expand or move clear windows outward on open. Bar→left is a change of axis: compute final free rectangle once, removing bar reservation and adding left reservation, rather than interpreting heights as widths. Other displays are unaffected.
6. Close priority: **edge-follow exception first**, then unchanged-frame restore, then leave alone. Compare all four frame components to last accepted frame within **2 pt** (implementation tolerance). Merely receiving an AX move event does not prove user intent. A changed window away from boundary is left as-is. A window created during details has no baseline and is not generally restored.
7. Edge-follow: eligible current window's near edge within **2 pt** of details inward boundary counts as literal touch. Existing avoidance leaves **8 pt** gap: also recognize boundary+8 pt within 2 pt, preserving that gap on return. Require positive overlap with details' vertical span and no cross-display ambiguity. This explicit exception can apply to windows created or manually resized during details, despite lack of original baseline; this does not grant them general restoration.
8. Left return: set near x to returning main inward edge (+ preserved gap), retain far x and current vertical frame; right is mirrored. Bar return: near x goes to the visible screen's left edge (literal screen-contact case has zero gap; preserve an existing avoidance gap), and enforce returning top/bottom reservation. Prefer resize to preserve the opposite edge; if minimum size refuses, shift accepted size to retain near contact and fit visible work area as closely as app permits. Re-read once, use bounded fallback, no retry loop/fighting app tilers. No whole-frame restore for changed edge-follow windows. Priority is intended near-edge contact subject to app/visible-frame constraints.
9. No movement, including restores/edge-follow, when avoidance off or trust lost. Drop mutation ledger on off/revocation; re-enabling establishes fresh baselines and applies current reservation. Never replay stale frames. Closed/fullscreen/minimized/other-Space windows skip and expire their restore claims. On quit, restore eligible unchanged frames if possible, then release observers/tasks.

The proposal's “moves nothing outward” is interpreted as **no blanket growth of clear windows when releasing space**. Explicit unchanged restoration and snapped-edge following remain required. Do not use that sentence to cancel the approved restore behavior.

## Data, timing and security contract

Bounded official-document reread performed here; **no API endpoint calls or credentials used**. Existing public capture remains historical, not a live count. These contracts are documented, not authenticated reconciliation:

- Account balance = `total_credits - total_usage`, not a key allowance; management key required. Preserve signed finite result rather than inventing a zero on error. [Credits](https://openrouter.ai/docs/api/api-reference/credits/get-remaining-credits).
- `/activity` covers 30 completed UTC days, management-only; `api_key_hash` scopes a key. Account default aggregates workspaces. Sum `usage` by UTC day and keep `byok_usage_inference` separate; missing completed days say “No activity reported”; malformed/partial financial responses cannot claim complete totals. Never chart today or perform 30 daily calls. [Activity](https://openrouter.ai/docs/api/api-reference/analytics/get-user-activity-grouped-by-endpoint).
- Key picker default workspace only, explicit offset pagination; include disabled/expired metadata to explain saved selections. Lazy pages, dedupe hashes, bounded traversal and “load more”; absent on one page does not mean deleted. Retain selected hash/name on unavailable state; never silently fall back to account chart. [Key list](https://openrouter.ai/docs/api/api-reference/api-keys/list-api-keys). Research records guide's 100-key pages; live paging consistency remains unverified.
- Setup validates `/key` management capability, then saves only explicit user input to own Keychain item. Management credential also permits key administration; explain that accurately. No read-only capability established. [Management](https://openrouter.ai/docs/guides/overview/auth/management-api-keys). No secret in config/logs/URLs; queued save/delete plus generation checks prevent stale account publication. Settings explicit validation may request credentials even without placed Credits; catalogue previews never read them.
- Public `/models?output_modalities=all`, omit offset/limit for full list. Schema auth boilerplate conflicts with prior observed unauthenticated success; do not add credentials to Models. Keep unknown modalities in All; strict sets define Text-only, output membership defines Text output. Stable ID, created descending with ID ties, missing created last. [Models schema](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties).
- Token prices are decimal strings per token, display ×1,000,000; preserve missing/negative as unknown/varies, sort last, never free. Zero token prices do not imply a `:free` variant. Avoid pretending token prices describe image/request/audio costs or conditional total cost. [Model guide](https://openrouter.ai/docs/guides/overview/models). Alias target may only be shown when supported by response evidence; do not invent from canonical slug.

Shared service with independent public catalogue and private balance/activity/key resources; immutable Sendable snapshots/parsers in Core. App service observable on main actor; transport, parsing, Keychain work use `@concurrent` boundaries, not detached tasks or blocking Security calls on UI actor. Check cancellation **and credential/demand generation after every await** before publication. Stop cancels work, keeps successful memory cache/deadlines; credential replacement clears private data immediately. No request per row or widget.

Merge demand by shortest active cadence; chart only when visible/configured layout needs it. Defaults assumed: balance 15 min (Manual/5/15/30/60), activity once per UTC rollover when needed, catalogue 60 min (Manual/15/30/60/180/360); picker on demand with ~30 min TTL. Manual-only gets one initial missing-data fetch then explicit actions. Details stale-open refresh respects freshness/cooldown, not unconditional request per open.

Shared 15-second manual gap; bounded Retry-After (case-insensitive, seconds or HTTP-date), backoff 429/503/transient errors; auth 401/403 stops retries until credential changes; malformed request 400 is actionable, not a retry loop. Retain stale successes and timestamps; cold errors show unavailable/setup, never fake money/zero chart. Compose a monotonic pacing deadline with injected wall date for UTC buckets; resume once, no missed-interval catch-up. Use existing scheduling primitives, not Timer/Combine/custom sleep loops.

Cache normalized search keys and derived ordering per snapshot/options, lazy stable-ID rows, local name/ID search; no fetch as user types. Spinner only in flight; age labels through demand-aware WidgetClock or coarse event updates, no frame clock. Unmeasured goals from research: zero recurring work without demand, no >16 ms UI processing stalls, <5 MB incremental retained catalogue, sensible 5 MB response cap. HTTP currently buffers full body; a post-read cap limits parsing, **not peak download memory**. Any stronger streaming cap must be justified and source-only in Opus stage. All budgets remain proposals until Sol measures.

Production seams: injectable async transport returning existing HTTP.Response; date/monotonic clock where deadline/UTC decisions need it; credential store boundary; AX window snapshot/apply adapter with accepted-frame readback. Pure Core request/parsing/filter/spend/transition geometry handles deterministic logic. Prefer small closures/value adapters over mock-only protocols/frameworks.
